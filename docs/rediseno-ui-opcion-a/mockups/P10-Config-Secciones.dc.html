Vencimientos

Se usa al cargar un lote si no escribes otro número. Entero de 0 a 365.

Así funciona

Al vender sale primero el lote que vence antes. Los vencidos no se venden solos: se retiran desde el producto. En Inicio ves los que están por vencer.

Patrón

  • Celular: cada sección es una pantalla con "Volver a Configuración"; crear o editar abre una hoja desde abajo.
  • Escritorio y tablet: menú de Configuración a la izquierda y la sección a la derecha (ver Usuarios y permisos en la fila de Configuración).
  • Categorías y Lugares en la tienda ya no están aquí: pasaron a Productos (ver tablero "Productos · categorías y lugares en la tienda"). En Configuración › Productos quedan como atajos con "En Productos".
  • Guardar muestra "Guardado" y vuelve al estado normal; si algo falla, el error queda en su campo.

Validaciones

  • Descuentos: % entre 0 y 100; para activar cada opción el máximo debe ser mayor a 0.
  • Invitar: correo válido y rol Cajero o Dueño. Siempre debe quedar al menos un dueño activo: la API rechaza quitar el rol o desactivar al último ("No se puede remover el último owner activo").
  • Vencimientos: entero 0–365.

Usuarios: acciones por fila

  • Hacer dueño / Quitar dueño, Desactivar / Activar (con confirmación). Invitaciones: Pendiente, Aceptada, Expirada, Revocada; Reenviar y Revocar.

API

  • PATCH /store (política de descuentos), /users (/role, /status), /user-invitations (/resend, /revoke) — existen.
  • Vencimientos: backend B4 (stores.default_alert_days, migración 040). Si no se hace, esta pantalla no se muestra y el aviso sigue fijo en 5.
  • Correo de invitación: depende del SMTP (Brevo) pendiente; mientras tanto, en desarrollo se muestra el enlace.
