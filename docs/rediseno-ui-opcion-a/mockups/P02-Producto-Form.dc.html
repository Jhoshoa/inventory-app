Caminos

  • Nuevo: Productos → "+ Nuevo producto". Al crear → detalle del producto con aviso "Producto creado".
  • Editar: Detalle → "Editar". "Guardar cambios" vuelve al detalle. "Cancelar" con cambios pide "¿Salir sin guardar?".
  • Foto: en celular "Tomar foto" abre la cámara; se optimiza antes de subir. Si la foto falla, el producto se guarda igual y se avisa.
  • Dónde está al crear (nuevo): se guarda justo después de crear con PUT /products/{id}/locations.

Crear sin salir del formulario (nuevo)

  • "+ Nueva" junto a Categoría abre una hoja (celular) o una ventana chica (escritorio) con Nombre y Prefijo del SKU. Al crear, la categoría queda elegida y el aviso del SKU se actualiza (PAN000001).
  • "+ Nuevo lugar" junto a Dónde está abre la hoja con Zona, Estante y Nivel. Al crear, el lugar queda marcado para este producto.
  • Lo escrito en el producto no se pierde: la hoja se cierra y se vuelve al mismo punto. Si la API falla, el error queda en la hoja.
  • Validaciones iguales a Productos › Categorías / Lugares: nombre requerido máx. 80, prefijo requerido máx. 8 letras y números (se pasa a mayúsculas), nombre y prefijo únicos (409, se muestra en su campo). Lugar: zona requerida máx. 50, estante máx. 50, nivel máx. 30 y solo con estante; no se repite sin importar mayúsculas (409).
  • API existente: POST /product-categories y POST /store-locations; sin cambios en el backend.

Validaciones (web y API)

  • Nombre: requerido, máx. 100. Nombre + unidad no se repiten (409).
  • Precio de venta: requerido, > 0. Costo: ≥ 0 (opcional).
  • Stock inicial: requerido al crear, entero ≥ 0. Al editar no se escribe.
  • Avisar si baja de: entero ≥ 0 (1 si se deja vacío). Unidad: máx. 20 ("unidad" si vacío).
  • SKU: máx. 50, único en la tienda (409). Con categoría y vacío: automático.
  • Código: máx. 100, único (409). Vacío: QR-{SKU} o uno al azar.
  • Descuento %: 0–100; Bs: no mayor al precio; ambos dentro de la política de la tienda. "Hasta": fecha futura y solo con descuento.
  • Vence el (solo al crear): fecha válida (años 2000–2100) y stock inicial > 0. Aviso: entero 0–365 (5 si vacío).
  • Foto: JPG/PNG/WebP, máx. 5 MB, se revisa que sea imagen de verdad.
  • Errores de la API (409) se muestran en su campo, no solo arriba.

Permisos

  • Solo dueño. El cajero que entra a la URL ve "No tienes permiso" (tablero de estados).

API

  • POST /products, PATCH /products/{id}, POST/DELETE /products/{id}/photo, GET/POST /product-categories, GET/POST /store-locations — existen.
  • "Así se ve al vender" y el margen se calculan en la web.
