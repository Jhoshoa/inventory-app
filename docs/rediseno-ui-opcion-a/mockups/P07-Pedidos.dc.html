Caminos

  • Celular: Más → Pedidos (con contador). Inicio también muestra "2 pedidos" arriba.
  • Tocar un pedido abre el detalle (hoja en celular, panel al costado en escritorio).
  • "Escribir por WhatsApp" abre el chat con el cliente y un mensaje armado con el pedido (como hoy); al volver se sugiere pasar el estado a "Contactado".
  • "Cobrar en Vender" (nuevo): abre Vender con estos productos y cantidades en la venta actual, el cliente ya escrito; al confirmar la venta se ofrece "Cerrar pedido". Productos borrados o sin stock se avisan y no se agregan.
  • Pedidos antiguos de un solo producto (sin lista) muestran el nombre del producto, sin total.

Estados

  • Pendiente → Contactado → Cerrado; se puede volver atrás. "Pago recibido" es aparte y se puede marcar o desmarcar.

Permisos

  • Dueño y cajero ven y responden pedidos (igual que hoy).

API

  • GET /storefront-requests (con pending_count), PATCH /storefront-requests/{id}/status, PATCH /storefront-requests/{id}/payment — existen.
  • Pestañas por estado: hoy la lista no filtra por estado (trae 50 y se filtra en la web). Con muchos pedidos, backend B7 (recomendado): parámetro status en GET /storefront-requests y conteo por estado.
  • "Cobrar en Vender" no necesita backend: la venta se crea con POST /sales como cualquier otra.
